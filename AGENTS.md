# HostsKeeper — инструкции для агентов Cursor

## Роли

| Роль | Кто | Обязанности |
|------|-----|-------------|
| **Оркестратор** | Ведущий Agent в этом проекте | Очередь этапов 0→14, приёмка по критерию, локальный коммит, старт следующего этапа; эскалация человеку при сомнениях |
| **Исполнитель этапа** | Тот же или субагент | Только один этап из промпта `doc/agent-prompts/stage-N.md` |
| **Человек** | Владелец | Команда на старт этапа 0 / 9 (PySide6) / пауза; эскалации; DoD с реальным Cursor по LAN |

Этап **0 и далее** — только по команде оркестратора (этап 0 — по явной команде человека).

## Инварианты (не нарушать)

- Секреты и адреса хостов **никогда** не отдавать через MCP, логи, `repr`, ошибки клиенту.
- Сессию SSH открывает **только человек**; ИИ — attach к вкладке.
- В MCP только вкладки UI; PuTTY/WinSCP — без MCP.
- HTTP MCP: предпочтительно стабильный app key (`?key=`) → все mcp-enabled вкладки; legacy `?token=` = 1 вкладка = 1 клиент.
- stdio MCP: без token; видит все mcp-enabled сессии + скрипты.
- Approve — на уровне сессии (default выкл = MCP read-only; вкл = write/run без модалки); CRUD скриптов без Approve.
- UI — класс connection manager (дерево + тулбар + вкладки), не чат-layout.
- Платформа v1 — Windows; ядро — Python.
- **Не делать:** облако, Multiplayer, агент на целевых хостах, non-interactive SSH как продукт, backup vault, импорт Termius.

## Правила работы исполнителя

1. Реализовать **только** указанный этап; не начинать N+1.
2. Закончить проверяемым критерием этапа (тесты/команды из промпта).
3. Краткий отчёт: сделано / как проверить / отклонения от `doc/`.
4. `doc/` менять только если код зафиксировал решение, которого не было в документах — и явно перечислить правки в отчёте.
5. Не коммитить секреты, `.vault`, ключи, реальные пароли.

## Правила оркестратора

1. Перед этапом — промпт `stage-N.md` + инварианты.
2. После этапа — прогнать/проверить критерий из плана.
3. При сомнении в приёмке — **остановиться и спросить человека**.
4. При успехе — локальный коммит с сообщением вида `Stage N: …`, затем следующий этап (кроме паузы после подготовки / по команде человека).
5. Не запускать этап 0 и этап 9 (миграция PySide6), пока человек не скажет явно.
