# Требования HostsKeeper v1

## Пользователи и роли

| Роль | Описание |
|------|----------|
| Человек | Единственный оператор сейфа: vault, открытие сессий, выдача MCP |
| ИИ (MCP-клиент) | Удалённый ассистент (в т.ч. Cursor): только разрешённые сессии и скрипты |

Даже если ИИ на том же ПК, подключение к сейфу идёт по той же схеме MCP (адрес `127.0.0.1` — частный случай).

## Функциональные требования

### Vault

- Сущности: **Host**, **Address**, **Credential**, **Script**.
- У Host несколько Address и Credential; при подключении пользователь комбинирует пару (есть defaults).
- Credential: логин/пароль и/или ключ.
- Теги и описания у каждой сущности.
- Секреты человек может просмотреть только в UI (отдельная кнопка).
- Шифрование vault паролем при старте приложения.
- Импорт из Termius / SSH config — не в v1.
- Export/backup vault — позже.

### Подключения

- Цели открытия: **вкладка UI** (встроенный SSH), **PuTTY**, **WinSCP**.
- В MCP попадают **только** сессии во вкладках UI.
- PuTTY / WinSCP — только для человека, без трансляции в MCP.
- Сессию открывает **только человек**. ИИ не инициирует логин.
- На целевые устройства стороннее ПО не ставится.

### Вкладка терминала

- Свой SSH-клиент внутри сейфа (общий PTY для человека и ИИ).
- Область терминала — функциональный минимализм (содержимое совпадает с тем, что видит ИИ).
- Обрамление приложения — стиль connection manager (см. [ui-guidelines.md](ui-guidelines.md)).
- В шапке/вкладке: **alias** сессии (ручной ввод + автопредложение вида `host-user-N`).

### Доступ MCP к сессии

- На каждую открытую вкладку: кнопка включения MCP + глобальные «подключить/отключить все».
- MCP на вкладке включается человеком; LAN-доступ — стабильный app key (gateway) или legacy 1 tab-token / 1 клиент.
- Token живёт, пока MCP включён для вкладки; при обрыве SSH и ручном reconnect **не меняется**.
- Token удаляется при выключении MCP или закрытии вкладки.
- При обрыве SSH кнопка MCP **не** снимается автоматически; tools возвращают `disconnected`.
- В Cursor mcp.json — стабильный URL с app key; в чат — **alias** вкладки (`session_attach`).
- Наружу через MCP: без адресов, учёток, секретов. Для сессии — alias/id/status и содержимое PTY.

### Подтверждение действий (Approve)

- Чекбокс **Approve** на вкладке (default **выкл**).
- Выкл → MCP только читает терминал; `session_write` / `scripts_run` сразу отклоняются (`approve_required`).
- Вкл → write/run разрешены без модалки и без таймаута.
- CRUD скриптов — без Approve.

### Скрипты

- Только shell-текст для вставки в PTY (не локальный раннер на сейфе).
- Параметры с подстановкой `{{name}}`.
- UI-формы параметров — не в v1.
- Хранение в том же зашифрованном vault.
- Чекбокс MCP управляет видимостью скрипта для модели: новый UI-скрипт скрыт по умолчанию; включённый шаблон доступен всегда, host-скрипт — при открытой MCP-вкладке этого хоста.
- MCP: создание / правка / удаление / список / запуск.
- `scripts_run` в выбранную/прикреплённую вкладку (gateway: alias/attach; legacy HTTP: token-сессия).

### Транспорт MCP

- **stdio** и **HTTP** сразу в v1.
- HTTP: bind на LAN, доступ по app key (gateway) или legacy tab token.
- stdio: доверенный локальный канал **без** token; видит все MCP-вкладки и все скрипты.
- Пока приложение закрыто — MCP недоступен.

## Нефункциональные требования

| Требование | Решение v1 |
|------------|------------|
| Платформа | Только Windows |
| Стек | Python (ядро + MCP + SSH/PTY) + UI **PySide6** (план миграции с временного FastAPI/static: [pyside6-migration.md](pyside6-migration.md)) |
| Стиль UI | Connection manager: дерево объектов, тулбар/ribbon, вкладки сессий, status bar ([ui-guidelines.md](ui-guidelines.md)) |
| Простота / расширяемость / надёжность | Приоритет выбора технологий |
| Офлайн как цель | Не требуется (но vault локальный) |
| Облачный синк | Нет |
| Multiplayer | Нет |
| Агент на целевых хостах | Нет |

## Сценарий работы с ИИ

1. Человек открывает SSH-вкладку, задаёт alias, включает MCP.
2. Копирует готовый URL в чат Cursor (или иной MCP-клиент).
3. ИИ подключается, получает alias через `session_info`, читает/подписывается на вывод, при необходимости пишет или запускает скрипты.
4. Человек параллельно работает в той же вкладке.
5. При обрыве — reconnect в UI; token и alias сохраняются, пока MCP включён.
